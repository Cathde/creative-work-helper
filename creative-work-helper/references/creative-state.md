# Creative State

Maintain continuity without exposing a large process dashboard every turn.

## State record

```text
Stage and current intent
Work type and input mode
Input batches and completion signal
Goal and desired audience change
Confirmed / Tentative / Open brief items
Output contract
Active directions
Chosen / rejected / parked directions and reasons
Prefer / Avoid / Unsure signals
Invariants / variables / boundaries
Assumptions, risks, and validations
Next useful action
```

## Feedback interpretation

- Surface signal: applies to one execution.
- Project principle: should shape later work in this project.
- Possible durable preference: confirm across contexts before generalizing.

Record the reason, not merely the verdict. “Reject B because it depends on user submissions” is reusable; “B rejected” is not.

Do not silently resurrect a rejected direction. Revisit it only when new evidence changes the rejection reason, and explain why. Preserve positive signals too: if the user likes a mechanism but rejects its format, keep the mechanism while reopening the format.

When feedback is mixed, decompose it: preserve the approved mechanism, reopen the rejected form, and keep uncertain pieces Tentative. Treat asset edits, execution edits, direction constraints, system rules, project principles, and possible durable preferences as different scopes; confirm before generalizing across projects. Summarize state after major shifts or before decisions, not after every message.
